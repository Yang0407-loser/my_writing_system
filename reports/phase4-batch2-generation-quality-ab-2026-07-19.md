# Phase 4 Batch 2：Context Broker 生成质量 shadow A/B

## 结论

`budgeted_broker` 没有通过有限 canary 门槛，继续保持 shadow。它将平均 Writer 输入从 12,406.4 降到 8,390.4 estimated tokens（-32.37%），但匿名辅助二审结果为 legacy 胜 6 组、Broker 胜 3 组、平局 1 组，Broker 胜加平局仅 40%，低于 80% 门槛；Broker 还新增了 1 个净连续性缺陷（legacy 1 个，Broker 2 个）。本批不回调预算、不恢复单项、不修改 Writer，并在此停止等待用户选择。

Batch 1 的 ContextItem 账本均值为 8,392.4；本批真正渲染 messages 后为 8,390.4。两者相差 2 token，来自账本与最终模板渲染的估算边界，不改变 32% 降幅结论。

## 固定实验

- A：当前 `legacy_full` Writer messages。
- B：按 Batch 1 冻结 keep/drop 决策重新组装的 `budgeted_broker` messages。
- 共 10 个冻结写作场景、20 次有效生成，模型 `deepseek-v4-pro`，temperature=0.5、top_p=0.9、max_tokens=8000。
- 当前客户端不支持 seed；输出顺序使用固定随机种子匿名化。
- Prompt、legacy RAG top-5 及顺序、角色/关系规则、四个风格旋钮、模型参数和当前写作请求均未改变。
- 生产 Writer 始终继续使用 A；10/10 冻结生产 Prompt hash 未变化。
- 生成正文仅存在于临时运行目录，报告只保留 hash、数值、标签和短证据，不提交正文。

后期场景为 Q1、Q4、Q10：Broker 胜 2、legacy 胜 1。不过 Q1 在运行核验时提前暴露了映射，只能作为辅助证据；Q4 的 Broker 输出出现已故母亲仍收礼的世界事实冲突。因此后期结果不能推翻总体失败结论，也不足以支持 canary。

确定性风格检查没有发现列明的 AI 套话。legacy/Broker 的完全重复段落数为 2/3，显式心理叙述信号为 18/20；机械计数、重复句式和情绪层次仍是风格基线问题，本批没有修改 Writer 或风格契约。

## 失败归因

失败不是 RAG top-5 或 hard 规则被删除：P0、P1、P2 均完整保留。主要风险来自整项删除的较早 recent originals 及部分 P3 世界状态：

- Q4 删除 S16.3、S17.1 和可选世界状态后，Broker 输出安排“留给周野妈妈”，与母亲已去世的事实冲突。
- Q6 删除 S6.1、S6.2 后，把“林晚周六没去”写成“面包店周六七点首次没开门”。
- Q7 删除 S5.3、S6.1 后，同一输出从“周六早上”跳成“明天周六”。
- Q8 两组都越过本节目标写到后续删帖、提问或当店员，说明该样本同时受当前 Prompt 边界控制问题影响，不能单独归罪 Broker。

这说明“较早两小节一律作为可选整项”过于激进；它们不只是长度来源，也携带相对日期、死亡状态和事件顺序。32% token 节省是真实的，但当前选择规则不能可靠识别这些隐式连续性依赖。

## 盲审与调用审计

- 先运行 hash、长度、段落重复和禁用套话等确定性检查，再完成匿名 Codex 辅助二审；provenance 为 `codex_assisted_review`，不是独立人工金标准。
- Q1 因轻量进程状态核验提前暴露映射，已明确标记；Q8 为平局歧义。两项无论如何归类都不能把 Broker 胜加平局提高到 80%，因此不存在会改变发布结论的待人工复核项，不再生成大表。
- 有 20 个带有效输出与 hash 的正式 A/B 调用。授权后的两次早期 Q1 合并进程尝试没有留下输出，无法确认服务端是否计费；另有一次仅含非项目文本的 7-input/1-output 连通性测试。它们不计入 A/B 指标，但属于可能的额外 API 成本。授权前被策略拒绝的请求未发送项目数据。
- 未获得可核验的单价快照，因此不把 token 换算为货币金额。

## 门槛与下一决策

通过：token 降幅、hard/关系违规、目标完成率、较早因果总数、事实错误总数、生产 hash、来源追溯。

失败：紧邻连续性不劣于 A、Broker 胜＋平 ≥80%。因此 `all_canary_gates_passed=false`，不建议有限 canary，更不能切换生产 Writer 输入。

本批按停止规则结束，不自动开始 Batch 3 或 Phase 5。下一步等待用户在以下方向中选择：

1. 调整整项预算：只针对被证明承载时间线/世界状态的较早 recent originals 提升优先级，再做一次独立验证。
2. 单独测试可追溯节级摘要：作为新假设，必须保留 source/hash/version，并重新验证事实完整性。
3. 放弃当前 Broker 路线，生产继续使用 legacy_full。

基于本轮证据，不选择“有限 canary”。
