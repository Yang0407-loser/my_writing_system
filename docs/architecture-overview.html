核心洞察: LLM 在自然语言上训练，对 JSON 数值参数几乎无感。{'emotion_intensity': 75} 和'文字像钝刀割肉'对生成质量的影响天壤之别。v0.9.1 将同一模式复用到交接笔记链——交接 JSON → 自然语言交接简报。

设计 5 · Agent 角色哲学 — "笔记员"而非"裁判"
flowchart TD WR["Writer 生成正文"] --> CHK["一致性检查 · ContinuityEditor · Reviewer"] CHK -->|"发现问题"| NOTE["记录事实 · 标注提醒 · warning 注入"] NOTE --> INJ["注入 Writer Prompt"] --> DECIDE["Writer 结合大纲+伏笔自主裁决"] DECIDE -->|"确认矛盾"| FIX["执行修正"] --> USER["用户最终审批"] DECIDE -->|"伏笔/假动作"| SKIP["跳过"] --> USER style DECIDE fill:#f59e0b,color:#000,stroke-width:2px style USER fill:#4ade80,color:#000

下游 Agent 只做笔记员——记录事实、标注提醒，不做强制裁决。Agent 会误判(如大纲安排的假死被当成矛盾)，硬阻断会让系统不可用。Warning 注入 + Writer 自主裁决的容错率远高于硬阻断。

设计 6 · 串行 vs 并行 · 黑板 vs 消息传递
flowchart TD subgraph WHY["为什么串行?"] DEP["Agent 间强依赖 · Writer 耗80%+时间"] --> BOT["并行其他9个不改善延迟"] BOT --> SAFE["串行 = 天然写屏障 · 黑板无需加锁"] end subgraph WHY2["为什么黑板?"] MSG["消息传递: N×M 耦合"] --> BB["黑板: Agent 只和黑板交互"] BB --> DEC["新增 Agent 不改其他代码"] end style SAFE fill:#4ade80,color:#000 style DEC fill:#4ade80,color:#000

串行不是偷懒，是分析后的选择。10 个 Agent 中 Writer 独占 80%+ 耗时。黑板模式解耦通信——每个 Agent 只和黑板交互，Coordinator 按需调度，低耦合、可独立替换。

设计 7 · Prompt 版本管理 & Token 监控 (v0.9.1 新增)
flowchart TD REG["PROMPT_REGISTRY · 14个模板"] --> VER["每个模板: version + used_by + changelog"] VER --> CALL["LLMClient.chat_completion(prompt_name=...)"] CALL --> LOG["日志: LLM [handover_brief v0.9.1] est_input=414tk"] CALL --> ACCUM["累计token: ContextVar per-task隔离"] ACCUM --> BB["每小节写完 → bb.set(task_id, token_usage)"] BB --> UI["前端状态栏: 42K tokens"] style REG fill:#7c8aff,color:#fff style UI fill:#4ade80,color:#000
